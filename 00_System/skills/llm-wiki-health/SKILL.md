# LLM Wiki 健康维护

## 目标

让 wiki 长期保持可读、可链接、可追溯、可演化。健康维护不是大改写，而是低风险地修复结构问题。

## 健康检查项目

1. 重复页面：同一概念是否有多个标题。
2. 孤立页面：没有进入索引、没有入链或出链的页面。
3. 断链：双链指向不存在页面。
4. 来源缺口：有事实但没有来源卡或 sources.csv 记录。
5. 日志缺口：近期实质更新没有写入 `20_Wiki/log.md`。
6. 索引缺口：稳定页面没有出现在 `20_Wiki/index.md`。
7. 问题堆积：`open-questions.md` 中已可回答的问题没有关闭或回写。
8. 页面膨胀：页面太长、主题混杂，需要拆分或重组。
9. 命名漂移：同类页面命名风格不一致。

## 维护原则

- 先做低风险修复：补链接、补索引、补日志、补来源引用。
- 合并或删除页面前要确认内容已迁移。
- 不要丢失用户原文或原始资料。
- 对不确定的大改动，先写维护建议，不直接执行。
- 中文知识库默认用中文维护。

## 推荐流程

1. 读取 `AGENTS.md`、`20_Wiki/index.md`、`20_Wiki/log.md`。
2. 扫描 `20_Wiki/` 的 Markdown 文件。
3. 生成健康问题清单，按风险分为可直接修复和需要确认。
4. 执行低风险修复。
5. 把较大结构调整写入 `30_Questions/open-questions.md` 或维护建议。
6. 按日期分段规则更新 `20_Wiki/log.md`。

## Change Log 规则

检查 `20_Wiki/log.md` 时，确保它按日期分段，而不是把所有记录堆在一个日期下面。

格式：

```markdown
## YYYY-MM-DD

- Added:
- Updated:
- Fixed:
- Open questions:
```

若发现新记录写在旧日期下，应移动到正确日期小节。修改后同步更新 frontmatter 的 `updated` 日期。

## 完成后

输出：

- 已修复的问题；
- 未修复但建议处理的问题；
- 涉及的文件；
- 下一次健康维护建议。
